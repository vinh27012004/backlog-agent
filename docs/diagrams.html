01

Architecture

Các thành phần logic và đường đi của một backlog item, từ lúc hiện trên trang match đến khi được nộp và chấm.

Cách đọc

  1. Trước giờ start, hệ thống tự chuẩn bị: pull code, cài dependency, build, index CodeGraph, tạo bản đồ hệ thống, rồi báo sẵn sàng.
  2. Codex Plugin của BTC xác thực đội với Game Master rồi spawn Orchestrator Agent. Agent gọi MCP control (code đội): control theo dõi trang match, giữ API key, báo "bắt đầu làm" và chỉ đánh thức agent khi có việc cần quyết.
  3. Mỗi item mới đi qua JEV và code để tạo triage: loại và deadline (code), mức độ, độ khó, item liên quan, chặn bẫy, chọn model cho fixer (JEV). Orchestrator xếp hàng theo triage.
  4. JEV trả lời mỗi câu hỏi trong khoảng 100 ms, kèm độ tin cậy. Dưới ngưỡng hoặc lỗi thì dùng luật tự quyết. Sau gate, JEV cũng chọn nộp / thử lại / bỏ trong các lựa chọn hợp lệ.
  5. Mỗi item chạy một codex exec với skill theo loại. Codex gọi các MCP tool: CodeGraph, bản đồ hệ thống, MVS runner, build/test, web_search. PI bị kẹt mới tách 2–3 Codex read-only kiểm giả thuyết song song.
  6. Gate do control tự chạy lại, không tin lời Codex báo xong. Mỗi loại item có profile riêng.
  7. FAIL: Log Condenser rút gọn log để re-plan nếu còn giờ và còn tiền. Nếu không thì áp luật tự quyết.
  8. PASS: nộp một lần lên Game Master, CR và BUG kèm evidence MVS. Grader chấm điểm chính thức.

Chú giải

  • Hệ thống của BTC
  • Điều phối và nộp bài (code đội)
  • Codex (dùng LLM, tốn $)
  • Tool và code thuần (không tốn $)
  • Gate
  • JEV (TypeSafe) · quyết định nhanh
  • Luật tự quyết
  • Dữ liệu chuẩn bị sẵn
  • Luồng chính, gọi tool
  • FAIL, re-plan
  • PASS
  • Giao tiếp với BTC
02

Infrastructure

Những thứ chạy thật trên máy của đội: các tiến trình, nơi lưu dữ liệu, vùng làm việc của Codex, và các kết nối ra ngoài.

Cách đọc

  1. Game Master đẩy source vào repo GitHub của đội. Bước chuẩn bị pull về, build sẵn, cache dependency và để app chạy sẵn cho PI tái hiện.
  2. Codex Plugin (BTC) xác thực đội, spawn Orchestrator Agent (một thread Codex) và theo dõi output, token của nó. Agent gọi MCP control của đội: control giữ URL, API key, team id trong .env, theo dõi trang match, hàng đợi, deadline theo giờ server, chạy gate, nộp bài và đếm chi phí.
  3. Mỗi item một tiến trình codex exec làm việc trong một git worktree riêng. Sandbox của Codex ở chế độ workspace-write và tắt mạng.
  4. Codex CLI gọi OpenAI API bằng key BTC cấp. Trạng thái và trace mỗi lần chạy được ghi vào SQLite cho monitor. Token và chi phí do plugin BTC theo dõi.
  5. MCP server chạy local qua stdio: CodeGraph, bản đồ hệ thống, MVS runner, Log Condenser, web_search. Đây là code thuần, không tốn $. Tra web chỉ đi qua web_search.
  6. Môi trường thi có mạng: orchestrator tải dependency ở bước chuẩn bị, hoặc khi CR thêm thư viện. Nhóm thi chỉ xem monitor, không can thiệp.

Chú giải

  • Bên ngoài máy
  • Tiến trình điều phối
  • Codex và OpenAI API
  • TypeSafe API (JEV)
  • MCP server, worktree
  • Lưu trữ, cache
  • Vùng hạn chế mạng
  • Gọi tiến trình hoặc service
  • Đọc và ghi dữ liệu
